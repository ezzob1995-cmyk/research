# 🔬 מערכת מחקר מחלקתי

מערכת אינטרנטית להזנת נתוני מחקר ע"י צוות המחלקה:
בדיקות דם עם חישוב **גיל ביולוגי לפי נוסחת לווין (PhenoAge)**, הערכת כפות רגליים, הערכת הזנחה עצמית — עם מסך מנהל, הרשאות, מעקב ביצועי צוות, מעקב התקדמות מחקר וייצוא לאקסל.

---

## מה יש במערכת

| למי | מה |
|---|---|
| **כל איש צוות** | כניסה עם שם משתמש וסיסמה אישיים · חיפוש מטופל לפי מספר סידורי · הקמת מטופל · הזנת בדיקות / הערכות (כמה פעמים שצריך לאורך השנה) · עריכת ההזנות שלו · "ההזנות שלי" |
| **מנהל** | יצירת משתמשים, סיסמאות ואיפוס סיסמה · הרשאות לכל איש צוות (אילו טפסים, הקמת מטופלים, עריכת הזנות של אחרים, צפייה בהתקדמות, ייצוא) · מסך התקדמות המחקר · ביצועי כל איש צוות · יומן פעולות מלא · הגדרות (מחלקות, יעדי גיוס, תאריכים) |
| **ייצוא** | קובץ Excel: גיליון מטופלים, גיליון לכל טופס (כל ביקור = שורה עם מספר ביקור), ביצועי צוות, מילון משתנים. אפשרות לשמות משתנים באנגלית ל-SPSS (ציונים כמספרים, כן/לא = 1/0) |

**חישובים אוטומטיים בזמן ההזנה:** גיל כרונולוגי (מחודש הלידה), PhenoAge, פער גיל (ביולוגי − כרונולוגי), BMI, ציון רגליים ורמת סיכון, ציון הזנחה ורמה.
**בדיקת תקינות:** ערך חריג (למשל אלבומין 42 במקום 4.2) מסומן בכתום עם אזהרת יחידות.

## לנסות עכשיו (בלי התקנה)

פותחים את `index.html` בדפדפן (או את האתר ב-GitHub Pages לפני שמחברים מסד נתונים).
המערכת תרוץ ב**מצב הדגמה** — הנתונים נשמרים רק בדפדפן.
כניסה: `admin` / `ChangeMe123!` ← החלפת סיסמה ← כפתור **"טען נתוני דוגמה"** בפס הצהוב.

---

## התקנה אמיתית (כ-20 דקות, חינם)

GitHub Pages מארח רק את הדפים. את הנתונים (משתמשים, סיסמאות, תוצאות) צריך לשמור במסד נתונים מאובטח — נשתמש ב-**Supabase** (חינם, לא של גוגל).

### שלב 1 — מסד הנתונים (Supabase)
1. נרשמים ב-https://supabase.com ← **New project**
   - שם: `research` · סיסמת DB חזקה (לשמור) · **Region: Central EU (Frankfurt)**
2. בתפריט השמאלי: **SQL Editor** ← **New query**
3. מדביקים את **כל** התוכן של `sql/schema.sql` ← **Run**. אמור להופיע `Success`.
4. **Project Settings → API Keys** (או **Data API**), מעתיקים:
   - **Project URL** — נראה כמו `https://abcdxyz.supabase.co`
   - **anon public** key (או **Publishable key**)
   - ⚠️ **לא** את `service_role` / `secret` — הוא אסור בדפדפן!

### שלב 2 — חיבור
פותחים את `js/config.js` וממלאים:
```js
SUPABASE_URL: 'https://abcdxyz.supabase.co',
SUPABASE_KEY: 'eyJhbGciOi...',   // ה-anon / publishable key
```

### שלב 3 — העלאה ל-GitHub
1. ב-GitHub: **New repository** (למשל `ward-research`). אפשר Public — אין בקוד שום מידע רגיש; הנתונים יושבים ב-Supabase.
2. **Add file → Upload files** ← גוררים את **כל** תוכן התיקייה (כולל התיקיות `js`, `css`, `vendor`, `sql`) ← **Commit**.
3. **Settings → Pages** ← Source: **Deploy from a branch** ← Branch: `main` / `(root)` ← **Save**.
4. אחרי דקה-שתיים האתר זמין בכתובת: `https://<שם-המשתמש>.github.io/ward-research/`

### שלב 4 — כניסה ראשונה
1. נכנסים עם `admin` / `ChangeMe123!` ← המערכת מחייבת להחליף סיסמה.
2. **הגדרות** ← שם המחקר, המחלקות המשתתפות, יעד גיוס, יעד בדיקות למטופל.
3. **ניהול צוות** ← "איש צוות חדש" לכל אחד מ-10 אנשי הצוות. המערכת יוצרת סיסמה זמנית ומציגה פרטי כניסה להעתקה. כל אחד יחליף סיסמה בכניסה הראשונה.

> 💡 בדיקה מהמחלקה: לפני ההדרכה לצוות, לפתוח את האתר ממחשב בבית החולים ולוודא ש-`supabase.co` לא חסום. אם חסום — לבקש מאבטחת מידע לאשר את הכתובת של הפרויקט.

## אבטחה ופרטיות

- **אין שמות / ת"ז / טלפונים במערכת** — רק מספר סידורי. טבלת הקישור (מספר סידורי ↔ מטופל) נשמרת בנפרד, במחשב בית החולים, אצל החוקר הראשי.
- נשמר חודש+שנת לידה בלבד (לחישוב גיל), לא תאריך לידה מלא.
- הטבלאות בסכמה פרטית שאינה נגישה מהאינטרנט. הדפדפן יכול רק לקרוא לפונקציות, וכל פונקציה בודקת התחברות והרשאה בשרת — לא רק במסך.
- סיסמאות מוצפנות (bcrypt). נעילה ל-15 דקות אחרי 5 ניסיונות כושלים.
- ניתוק אוטומטי אחרי 20 דקות ללא פעילות (ניתן לשנות ב-`config.js`). סגירת הדפדפן = יציאה.
- כל פעולה (כניסה, הזנה, עריכה, מחיקה, ייצוא, שינוי הרשאות) נרשמת ביומן. מחיקה היא "רכה" — הנתון נשאר במסד.
- **לפני תחילת העבודה:** לוודא שאחסון נתונים מתוך-השם (pseudonymized) בענן חיצוני תואם את אישור ועדת הלסינקי ואת נהלי אבטחת המידע של בית החולים, ולציין זאת בפרוטוקול אם נדרש.

## שינויים נפוצים

**להוסיף / לשנות שדה או טופס שלם** — הכול בקובץ `js/forms.js`:
```js
{ key: 'hb', label: 'המוגלובין', type: 'number', unit: 'g/dL', min: 5, max: 20, step: 0.1 },
```
סוגי שדות: `number`, `text`, `textarea`, `date`, `select`, `radio`, `checks` (בחירה מרובה), `yesno`, `score` (אפשרויות עם ניקוד).
אחרי הוספת **טופס** חדש — לתת לצוות הרשאה אליו במסך ניהול צוות.
⚠️ לא לשנות `key` של שדה שכבר הוזנו בו נתונים (הנתונים הישנים לא יופיעו תחת השם החדש).

**סקאלת ההזנחה** — כרגע כלי פנימי (10 תחומים × 0–2). אם הפרוטוקול מאושר עם כלי מתוקף, מחליפים את השאלות ב-`forms.js`.

**גיבוי** — ייצוא Excel תקופתי (למשל פעם בשבוע) ושמירה במחשב מאובטח. ב-Supabase החינמי אין גיבוי אוטומטי ארוך-טווח.

**פרויקט Supabase חינמי נכנס ל"שינה" אחרי שבוע ללא שימוש** — אם המחקר בהפסקה, נכנסים ל-Supabase ולוחצים Restore. הנתונים לא נמחקים.

## נוסחת PhenoAge

Levine ME et al. *An epigenetic biomarker of aging for lifespan and healthspan.* Aging (Albany NY) 2018;10(4):573-591.
9 סמנים: אלבומין, קריאטינין, גלוקוז, CRP, % לימפוציטים, MCV, RDW, ALP, WBC + גיל כרונולוגי.
ההזנה ביחידות המקובלות בישראל; ההמרה ליחידות המקור נעשית בקוד (`js/phenoage.js`). CRP של "<0.1" מוזן כ-0.1.

```
js/phenoage.js      חישוב גיל ביולוגי
js/api.js           תקשורת עם השרת + מצב הדגמה
js/app.js           ממשק המשתמש
css/style.css       עיצוב
vendor/             ספריית ייצוא Excel (SheetJS) — מקומית, בלי תלות באינטרנט חיצוני
sql/schema.sql      ← מריצים פעם אחת ב-Supabase
```
